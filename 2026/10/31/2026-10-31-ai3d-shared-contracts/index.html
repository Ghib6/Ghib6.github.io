从项目早期讲起：AI 游戏平台的共享契约与 JSON 数据边界

发表于2026-10-31|更新于2026-10-31|AI 3D 游戏生成
|总字数:2k|阅读时长:6分钟|浏览量:|评论数:

游戏生成平台的用户需求要经过表单、Web 服务、后端控制器和业务服务，最终产生项目与任务记录。即使前后端都使用 TypeScript，也需要明确规定请求实际长什么样、哪些输入能够接受，以及数据库数据怎样变成 JSON。

本文继续回看项目早期基础。对照 2026 年 8 月 3 日提交 fabfabfb，后端的 common/zod-validation.pipe.ts 与 common/json.ts 仍与当时一致。共享契约文件后来持续扩展，本文使用当前代码中的字段举例，不把新增字段误记为早期已有功能。

背景：同一个需求跨过几层边界

以创建游戏为例，用户填写需求和模型配置，Web 端组织请求，后端验证后创建项目并提交生成任务。错误可能发生在不同位置：需求只有空格、模型名称不在支持列表、资源 ID 不是约定的字符串，或者响应带有不能直接序列化的 BigInt。

项目使用 @bishe/contracts 集中保存共享 Schema 和相关类型，后端通过专门的 Pipe 执行解析；业务完成后再把返回对象转换为 JSON 可传输的数据。

    flowchart TD
  A[用户填写游戏需求] --> B[Web 端组织请求]
  B --> C[后端控制器接收 JSON]
  C --> D[共享 Schema 执行 safeParse]
  D --> E{校验是否通过}
  E -->|否| F[返回 400 与校验问题]
  E -->|是| G[业务服务检查权限与资源状态]
  G --> H[创建项目与生成任务]
  H --> I[转换 BigInt 等返回值]
  I --> J[Web 端取得字符串 ID]

这是一条简化的数据路径。图中的共享 Schema 不意味着所有 Web 操作都以完全相同方式执行前置校验，后端仍需独立验证实际收到的请求。

输入格式与业务资格分开判断

一个资源 ID 即使是纯数字字符串，也可能不存在、属于别人或尚未准备好。当前项目创建服务会进一步检查引用图片的所有者、状态、类型和格式，检查选定资源能否作为输入。

同样，修改请求的 instruction 达到长度要求，也不代表请求者有权编辑对应项目。项目归属仍由业务服务检查，身份则来自认证链路。

共享 Schema 适合表达可局部确定的结构和约束；需要当前数据库状态的判断留在业务服务。这样错误来源也更清晰：格式不符在入口被拒绝，资源状态或权限不符在业务检查中被拒绝。

还有一个范围边界：@Body(...) 只解析请求体，不会自动验证 URL 路径参数。当前若干项目接口直接用 BigInt(projectId) 转换路径字符串，因此不能宣称共用 Schema 已经覆盖所有路径、查询和响应数据。

数据库 ID 为什么以字符串返回

项目使用 BigInt 表示数据库中的部分 ID。标准 JSON 无法直接序列化 JavaScript BigInt，把较大的整数先转成 Number 还可能失去精度。因此传输层用十进制字符串表示这些 ID。

这个工具仍有类型与数据范围限制

toPublicJson<T> 的返回类型仍然写作 T，但运行时 BigInt 和 Date 已经发生转换。末尾 as T 只是类型断言，不能把转换后的字符串重新变回原始类型。若调用者继续按 bigint 操作，就会形成静态声明与运行时值之间的错位。

JSON 往返也会丢失对象原型，不能处理循环引用，还会按 JSON 规则处理 undefined 等值。因此它适合当前这类面向接口的普通数据，不能当作任意 JavaScript 对象的通用深拷贝。

另一个需要注意的点是，toPublicJson 只负责转换，不负责剔除私人字段。业务服务必须先选出允许公开的数据，再调用转换工具；序列化成功并不等于信息可以公开。

今天重跑了现有契约测试：

测试通过，覆盖现有测试文件中的合法和非法输入样本，包括发布、内容及审核约束。它是 Schema 层的测试，不能作为浏览器请求、所有项目输入边界、数据库业务校验或 JSON 工具的完整验收。本文其余链路来自源码核对，今天没有修改应用代码或调用游戏生成模型。

这套基础最值得复用的做法，是把可执行规则放在共享包，入口使用解析后的结果，业务层继续检查权限与状态，返回端明确处理数据表示。遇到字段类型不一致时，沿这几层分别定位，比单纯增加一个 TypeScript 断言更容易找到原因。

对于 AI 游戏平台，模型和工作流会不断变化，而请求契约与传输边界决定了各模块能否稳定协作。维护这些基础时，应同时关注规则、真实数据和公开接口类型，保证它们表达的是同一种约定。
